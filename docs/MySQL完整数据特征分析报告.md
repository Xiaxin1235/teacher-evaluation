## 4. 归一化体系（核心问题区）

### 4.1 公式验证

对 200,000 条抽样验证：

```
normalized_value = (value - min_val) / (max_val - min_val)
```

匹配率 **99.90%**（199,807 / 200,000）。未匹配的 193 条为精度差异（部分记录仅保留 3 位小数，如 `0.429` vs `0.42857142857142855`），属分批计算留下的不一致。

### 4.2 量程来源：实测极值，而非理论满分 🔴

**83 题的实测最大值与 `question_min_max.max_val` 逐一完全相等**，无一例外。这证明量程是从实际数据里 `MAX(value)` 算出来的，**不是题目理论满分**。

后果：**任意一条脏数据都会永久毁掉该题的归一化**。

### 4.3 被脏值主导的题目（12 题，量程 ≥ 1e6）

| 题 | 题干 | 官方 max | 非零均值 | 均值/max |
|---|------|--------:|--------:|--------:|
| Q29 | 校级领导信息化培训总计人次 | **100,000,000,000,000** | 299,961,399 | 0.000003 |
| Q38 | 信息技术课程教师人数 | **78,956,735,973** | 486,988 | 0.000006 |
| Q40 | 参加信息化专项培训教师比例 | **15,909,211,197** | 49,757 | 0.000003 |
| Q47 | 听课教室开课课时数 | **15,891,588,662** | 273,234 | 0.000017 |
| Q41 | 信息化校本培训次数 | **99,999,999,999** | 510,247 | 0.000005 |
| Q44 | 参加教育信息技术比赛数 | **99,999,999,998** | 1,244,462 | 0.000012 |
| Q45 | 教育云平台晒课数量 | **99,999,999,998** | 2,458,961 | 0.000025 |
| Q43 | 校本培训覆盖教师比例 | **5,455,454** | 91.94 | 0.000017 |
| Q18 | 智能学习空间共计 | **9,999,999,999** | 237,517 | 0.000024 |

典型脏值：`999999999`、`99999999999`、`12345678`、`123456789`、`1048576`（= 2²⁰，明显误填）、`100000000000000`（100 万亿人次培训）。

**Q40「教师比例」量程达 159 亿**、**Q43「覆盖教师比例」量程达 545 万**，而比例类指标理论上限为 100 —— 这类污染尤其荒谬。

### 4.4 压缩超 100 倍的题目（27 题，占 32.5%）

除上表 12 题外，还有 15 题均值/max < 0.01：
Q31(90000)、Q32(226666)、Q33(224333)、Q35(22222)、Q36(10000)、Q37(20000)、Q46(10000)、Q50(10000)、Q58(100000)、Q65(5000)、Q68(5000)、Q69(5000)、Q70(5000)、Q80(20000)、Q81(20000)。

其中 Q31–Q37 是**经费占比**类，理论上限 100，实测量程却达 90000 / 226666 / 224333。

按维度看，受损最重的是**保障机制**（16 题，max 合计 1.0×10¹⁴）和**数字素养**（9 题，max 合计 2.26×10¹¹）。

### 4.5 其他量程异常

| 问题 | 题目 | 说明 |
|------|------|------|
| **除零风险** | **Q22** | min=1, max=1 → (v−1)/(1−1) = 0/0 |

## 5. 原始宽表（regional.school_data）

### 5.1 结构

97 列 = 14 个基础列 + 83 个 `question_N` 文本列，374,887 行。

### 5.2 原始答案形态

原始答案是**多选题选项列表**，例如：

```
question_1 : [\B.语文\, \C.数学\, \D.英语\, \E.科学\, \F.美术\, \G.音乐\, \H.体育\, \I...]
question_3 : [\B.网络备课\, \C.网络教学\, \D.网络教研\, \G.教学资源制作\, \H.教学资源管理\]
question_4 : 100
question_31: 15.25
```

→ **数值化规则 = 选项个数**。这解释了 Q1 量程为何是 21（共 21 个学科选项）、Q3 是 11、Q7 是 13。

### 5.3 串列错位 🔴

从 **`question_59` 起，25 列内容出现明显串位**，单列内混入了多个题目的答案：

```
question_59 : \D.名校网络课堂\],[\E.观摩式\],[\B.教师教学应用分析\],[\D.地市级平台\],[\Yes\],[\Y
question_60 : \F.餐卡\],B.否.1,[\C.教学楼\
question_62 : \F.生活区\],[\C.省级培训\],1,[\D.制定学校教师信息技术应用能力培训计划\],30,10,10,20,1
```

这 25 列（Q59–Q83）中，Q71–Q83 在规范化库里覆盖率为 100%，但**其原始来源已错位**。若数值化管线基于该宽表生成，Q59–Q83 的取值可信度需重新核验。

## 7. 表间关联关系

```
questions (83) ──1:N──► school_answers ◄──1:N── schools (374,887)
                              │
                              │ question_id
                              ▼
                     question_min_max (83)
```

| 关系 | 基数 | 约束 |
|------|:---:|------|
| `school_answers.school_id` → `schools.id` | N:1 | ✅ FK, ON DELETE CASCADE |
| `school_answers.question_id` → `questions.id` | N:1 | ✅ FK, ON DELETE CASCADE |
| `question_min_max.question_id` → `questions.id` | 1:1 | ❌ **无约束** |
| `questions.level1/2_name` | 层级 6 → 13 → 83 | ❌ 无维度表 |

**问题**：`question_min_max` 与 `questions` 本应 1:1，却没有任何约束，若 `questions` 增删题目，量程表会静默失配。

### 7.1 维度层级

```
一级维度 (6)
├─ 基础设施 (18题) ─ 终端 / 教室 / 网络
├─ 教育治理 (17题) ─ 学校治理 / 网络安全
├─ 保障机制 (16题) ─ 财力 / 组织 / 人力保障
├─ 教育教学 (12题) ─ 教学方式 / 教学评价
├─ 数字资源 (11题) ─ 资源应用 / 资源规模
└─ 数字素养  (9题) ─ 教师数字素养
```

三级权重（level1/2/3_weight）**全部恒为 1.0** → 当前是等权算术平均，权重体系未启用。

## 8. 问题清单与建议

| 优先级 | 问题 | 建议 |
|:---:|------|------|
| **P0** | 归一化量程取自实测极值，12 题被脏值主导 | 改为**理论满分**口径（比例类=100，计数类=选项数）；或用 P99/Winsorize 截尾后再算量程 |

| **P1** | 全矩阵 47.61% 零值填充 | 未作答应存 `NULL` 而非 0，或用 `is_answered` 标记位区分 |
| **P1** | 宽表 Q59–Q83 串列错位 | 重新导出该区间，核对列边界与转义 |
| **P1** | 6 题 min=1（计数题） | 与业务确认最小值口径 |
| **P2** | `question_min_max` 无主外键 | 加 `PRIMARY KEY(question_id)` + FK |
| **P2** | email/phone 含 NA、城市名 | 入库前做格式校验与占位符识别 |
| **P2** | 仅 22 题全年份可比 | 建立"题目-年份"元数据表，分析时自动限定可比题目 |
| **P3** | 归一化精度不一致（3 位 vs 全精度） | 统一 `double` 存储，避免分批写入差异 |

### 8.1 分析使用建议

1. **统计前必须剔除零值填充**：`WHERE value > 0`，否则所有均值被拉低约一半。
2. **跨年趋势只用 22 道全年份题**；2023 年数据不可与 2020 年直接全题对比。
3. **暂不使用 Q4、Q18、Q29、Q31–Q47、Q58、Q60、Q80、Q81 的 normalized_value**，除非先修复量程。
4. **Q64–Q66、Q70（终端配备数量）覆盖率 < 50%，不建议纳入评估**。
5. 如需可信的综合评分，建议**基于 `value` 重新归一化**，而非复用库内 `normalized_value`。

## 附录：主要口径

- 全矩阵行数 31,115,621 = 374,887 × 83，由逐行解析确认（非估算）。
- "有效作答" = `value > 0`；"零值填充" = `value = 0`。
- 年份归属通过 `school_answers.school_id` 关联 SQLite `schools.year` 得到（374,887 条映射完整）。
- 归一化公式经 200,000 条抽样反向验证，匹配率 99.90%。
- 压缩倍数 = 非零均值 / `question_min_max.max_val`。
- 宽表解析获 374,842 行（另有 45 行因含特殊字符未解析，占比 0.012%，不影响结论）。
